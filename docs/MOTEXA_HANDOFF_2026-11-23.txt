1. أين وصل العمل؟
التركيز الأخير كان على صاحب السيارة: الرئيسية السينمائية، شاشة أنواع الميكانيكيين الثلاثة، ثم رحلة الذهاب للورشة المرتبطة فعليًا بالخادم وPostgreSQL. آخر نقطة توقّف بصري: صور خيارات الميكانيكي الثلاثة رفضتها صاحبة المشروع، ولم يتم اعتمادها تصميمًا نهائيًا. صورة RAC الخارجية كانت مرجعًا في المحادثة فقط ولم تُدمج في التطبيق. طلبت صاحبة المشروع إيقاف التعديلات، ثم حفظ النسخة الحالية على GitHub. لا تعاود تصميم الصور تلقائيًا بسبب فتح هذا التقرير.

2. هيكل المشروع
mobile: React Native / Expo 57، React، Reanimated، Gesture Handler، Expo Router.
backend: Express / TypeScript، Prisma، PostgreSQL.
docs: تقارير، أدلة مراحل التصميم، نتائج اختبار وصور مراجعة.
ملفات قاعدة البيانات الوصفية والترحيلات داخل backend/prisma، لكن بيانات PostgreSQL الحية خارج مجلد المشروع. GitHub لا يحفظ بيانات قاعدة البيانات تلقائيًا.

3. دخول صاحب السيارة وسياراته
مسار تسجيل الدخول موجود، وتحته إنشاء حساب. إنشاء حساب صاحب السيارة منفصل عن منحه صلاحيات أدوار أخرى. الاسم والبريد ورقم الهاتف محفوظة في الحساب.
إدارة أكثر من سيارة: إضافة، اختيار السيارة النشطة، تعديل، إزالة/أرشفة، وصورة خاصة للسيارة. الحقول الحالية للسيارة: الماركة، الموديل، السنة، نوع الوقود، الصورة وبيانات النسخة/التوقيت. لا تفترض وجود VIN أو رقم لوحة أو ناقل حركة أو عدّاد كيلومترات؛ هذه ليست ضمن حقول OwnerVehicle الحالية.
الطلبات مربوطة بسيارة مملوكة للمستخدم ويُحفظ وصف السيارة مع الطلب.

4. الرئيسية السينمائية
الواجهة الحالية في OwnerAutomotiveHome.tsx وOwnerHome.tsx. تستخدم صور مرسيدس التي زوّدتها صاحبة المشروع، بالمسار assets/cinematic/supplied. الترتيب الحالي يبدأ من المقصورة، ثم يكشف الخارج بقناع مرتبط بالسكرول، ثم تفاصيل وخدمات. التمرير العكسي يعكس المشهد. أُبطئ تقدم الرحلة لتوجد مساحة للترحيب ثم شرح الخدمات.
هذه حركة صور ثنائية/شبه ثلاثية الأبعاد، وليست نموذج 3D أو حركة كاميرا فعلية. لا تدّعِ وجود 4K حقيقية: الصور المورّدة تقارب 1K–1.3K في أبعادها الأصلية.
نقاط الخدمات وأزرارها مربوطة بالوجهات الحالية. أسفل المشهد لوحة خدمات بلون بيج شفاف متداخلة مع المشهد: ميكانيكي، قطع، ونش، AI، ورابط متابعة الطلبات.
الشعار والعنوان الانسيابي حازا قبولًا نسبيًا. العنوان العربي الحالي: عناية تليق بسيارتك. لا تعتبر كل صور الخدمات معتمدة بصريًا.
أُزيل تكرار ملخص السيارة والطلب التجريبي والتذييل الإضافي من الرئيسية.

5. أنواع الميكانيكي
WORKSHOP: المستخدم يذهب للورشة.
ON_SITE: الميكانيكي يأتي لموقع السيارة.
ONLINE: طلب استشارة عن بُعد.
الثلاثة يفتحون الدليل بحسب الخدمة ويستخدمون الطلبات الحقيقية الموجودة. تحسين توزيع الشاشة موجود: صورة أعلى وكرت تفاصيل أسفلها بتداخل خفيف. الصورة والنص لهما دعم عربي/إنجليزي وثيم فاتح/داكن. صور هذه الشاشة الحالية مرفوضة ذوقيًا وتحتاج مراجعة لاحقة، وليست جاهزة للاعتماد النهائي.
لا تفترض أن ON_SITE لديه تتبع حي لحركة الميكانيكي أو أن ONLINE لديه مكالمات فيديو/دردشة مكتملة؛ هذه القدرات لم تُنفذ أو تُثبت في هذه المرحلة.

6. رحلة الورشة المنفذة وظيفيًا
اختيار السيارة والخدمة، عرض الميكانيكيين المعتمدين النشطين الذين يقدمون الخدمة، تصفية المدينة، عرض الملف والتخصص والخبرة والعنوان، الاطلاع على نقطة الورشة، تعبئة المشكلة والهاتف، مراجعة الطلب، إرساله، متابعة رد الميكانيكي، ثم الرحلة والوصول وإتمام الخدمة.
حالات الطلب الحالية: NEW، ACCEPTED، IN_PROGRESS، COMPLETED، DECLINED، CANCELLED.
لا يوجد تأكيد موعد زمني محجوز بمجرد إرسال الطلب. الإلغاء متاح للطلب الجديد قبل القبول. يوجد تحقق من ملكية الطلب والسيارة، ومفاتيح لمنع تكرار الحفظ والطلب، وحماية النسخ المتزامنة. لا يُقبل أكثر من طلب نشط واحد للميكانيكي في نفس الوقت.
الدليل الحالي ليس ترتيبًا حسب المسافة الفعلية، ولا توجد تقييمات أو أسعار مختلقة.

7. GPS الفعلي وحدوده
نقطة الورشة تُحفظ عبر الخادم. بعد قبول الطلب، يستطيع صاحب السيارة بدء رحلة GPS أثناء فتح الشاشة. مشاركة موقعه مع الميكانيكي اختيارية. المواقع تُرسل للخادم وتُحفظ في PostgreSQL، مع جلسة وتسلسل وتوقيت ودقة.
الخريطة تستخدم Leaflet/OpenStreetMap داخل WebView على الهاتف وiframe على الويب، ومسار القيادة عبر OSRM مع إمكانية فتح الملاحة الخارجية. فشل المزوّد الخارجي له رسالة وخيار بديل.
تأكيد الوصول مرتبط بالقرب من الورشة وقراءة دقيقة وحديثة، وليس زر وصول وهميًا. تُزال المشاركة والموقع عند تأكيد الوصول، وتُوقف المشاركة عند مغادرة الشاشة/الخلفية أو بدء الخدمة. القراءة المشتركة تنتهي بعد نحو 45 ثانية دون تحديث.
أُصلح تنظيف الجلسة عند تغيرها/إيقافها، وإخفاء الموقع الضعيف أو القديم، وملاءمة الخريطة للمسار عند وصوله.
لم نختبر قيادة فعلية بهاتف Android. اختبار المتصفح استخدم إحداثيات مضبوطة، بينما API والحفظ والصلاحيات كانت فعلية.

8. الطلبات والحساب والخدمات غير المكتملة
طلباتي يحتوي على الجارية والسابقة والتفاصيل والتحديث والإلغاء وحالات الخدمة. الحساب وإدارة البيانات موجودان ويحتاجان مراجعة منتج شاملة قبل إعلان جاهزية نهائية.
قطع الغيار، الونش والـAI لديهم وجهات تعريفية مع بيان عدم جاهزية الخدمة؛ ليست أنظمة طلب/مخزون/إرسال ونش/تشخيص عاملة بالكامل.
الدفع والأسعار مؤجلان بطلب صريح. لم تُضف بوابة دفع أو أسعار ميكانيكيين أو فواتير. التقييم بعد الخدمة غير منفّذ في هذه المرحلة.

11. نموذج Phase 1 المنفصل
يوجد نموذج dev منفصل /cinematic-lab ومجلد components/cinematic ووثائق docs/cinematic. إعداد enabledInMainFlow=false، ويستخدم placeholders مرسومة بالكود افتراضيًا. scenes.config.ts عقد استبدال وسائط هذا النموذج فقط؛ صور Home الحالية مضبوطة في owner-home-media.ts.
توجد صورة AI سابقة مرفوضة ومؤرشفة في assets/cinematic/generated، ومذكورة في MANIFEST. لا تُعد إدخالها افتراضيًا ولا تُولّد صورًا جديدة دون طلب. العبارة الأولى القديمة في MANIFEST عن عدم وجود صور مولّدة سابقة تتعارض مع قسم الصورة المرفوضة المضاف لاحقًا؛ القسم المؤرخ يوضّح الحالة الفعلية.
لم نطبق Three.js أو WebGL أو محرك 3D جديد أو فيديو مولد.

12. التشغيل والحفظ
آخر منفذ مستخدم للواجهة: 58134؛ وآخر منفذ Backend: 5055. وجود الرابط لا يضمن أن الخادم يعمل بعد إغلاق الجلسة.
تحقق من .env محليًا دون نشره. كان EXPO_PUBLIC_API_URL موجّهًا إلى عنوان شبكة محلية، وقد يحتاج تحديثًا عند تغيير الجهاز أو الشبكة.
أوامر بناء TypeScript في كل مجلد: node node_modules/typescript/bin/tsc --noEmit.
تشغيل Backend من backend: npm run dev. تشغيل الواجهة من mobile: npm run web أو npm start بعد تثبيت الاعتماديات وضبط البيئة.
لا ترفع كلمات المرور أو الرموز أو .env أو بيانات قاعدة البيانات أو الملفات الخاصة. ملفات Prisma والترحيلات تُرفع، وPrisma Client المولّد يعاد توليده أثناء الإعداد.
